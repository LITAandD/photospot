# 포토스팟 앱 1.0 출시 후보

Expo SDK 54 / React Native 0.81.5. 출시 대상은 Android·iOS입니다. 웹은 화면 검증과 데모용입니다.

## 실행

```sh
npm --prefix client ci
npm --prefix client run build
npm --prefix app ci
npm --prefix app start
```

위 명령은 저장소 루트에서 실행합니다. API는 루트의 Docker Compose 구성으로 실행하고, `app/.env.example`을 참고해 앱에서 접근 가능한 서버 주소를 설정합니다. 실제 휴대폰에서는 PC의 LAN IP, Android 에뮬레이터에서는 `http://10.0.2.2:8000`을 사용하세요.

```sh
npm --prefix app run demo -- --port 8081
```

이 명령은 웹 앱(8081)과 로컬 개인화 계산 서버(127.0.0.1:8001)를 함께 실행합니다. 루트 `.venv`에 `requirements.txt`가 설치되어 있어야 합니다. 프로필·생년월일·촬영일을 실제로 계산하고 `storage/places.sqlite3`의 OpenStreetMap 장소를 조회합니다. 2026-10-06 현재 서울·부산·제주·강릉 주변 10,874곳이 들어 있습니다. 새 환경에서 DB가 없다면 아래 수집을 먼저 실행합니다. 개인정보 안내를 확인한 뒤 체험용 로그인을 누릅니다. 프로필·오행 비율·저장 목록은 이 브라우저에 보관되어 새로고침 후에도 유지됩니다. 생년월일시·사주 기둥은 저장하지 않습니다. 로컬 계산 서버는 입력을 저장하지 않습니다. 회원 탈퇴로 브라우저 데이터를 지울 수 있습니다.

```sh
python -m pipeline.place_catalog --regions seoul,busan,jeju,gangneung
```

조회 중 외부 지도 API를 호출하지 않으며 갱신은 위 명령으로 직접 수행합니다. DB가 비어 있어도 샘플로 대체하지 않습니다. [OpenStreetMap 출처·ODbL](https://www.openstreetmap.org/copyright)은 앱의 목록과 상세에 표시합니다. 현재는 장소 유형·거리 기반 탐색이며 장소 사진·조명·혼잡도·촬영 적합도는 미검수입니다. 영업시간은 원본에 등록된 값만 표시하므로 방문일의 영업 여부는 별도 확인이 필요합니다. [실제 데이터 실행 안내](../REAL_DATA_TEST.md)에 범위와 갱신 방법을 정리했습니다.

현재 미리보기 CORS는 8081 포트만 허용합니다. 다른 포트로 실행하려면 `api/preview.py`의 허용 출처를 맞추세요. 체험 모드의 실제 사진 업로드는 지원하지 않습니다. 소셜 인증·PostGIS 연동은 이 모드에서 검증하지 않습니다. 실제 개발 로그인은 서버 `DEV_LOGIN=1`, 앱 `EXPO_PUBLIC_DEV_LOGIN=1`이 필요하며 운영에서는 금지됩니다.

홈의 **전체 / 카페 / 여행 명소 / 축제·행사 공간**으로 종류를 고를 수 있습니다. 여행 명소는 산·동굴·폭포·테마파크·공원·해변·박물관 등을 포함하고, 축제·행사 공간은 축제장·공연/문화 공간·전시/컨벤션 공간을 포함합니다. 장소 분류는 실제 행사 개최 일정과 별개이며 행사 일정은 아직 연동하지 않았습니다. 선택한 종류는 사주·일진 추가 추천에도 유지됩니다.

## 주요 화면

장소에 사진이 연결되어 있으면 추천 카드·저장 목록·상세에 표시합니다. 상세 갤러리에서 이전/다음 사진과 썸네일을 선택할 수 있고, 작가·라이선스·출처·원본 사진 링크를 확인할 수 있습니다. 로컬 사진 연결 명령은 `python -m pipeline.catalog_photos --scan --link`이며 [실제 데이터 안내](../REAL_DATA_TEST.md)를 참고하세요. 사진 연결만으로 분석 점수를 만들지는 않습니다.

DB 건수·수집일·연결 상태는 사용자 화면에 표시하지 않습니다. 홈과 장소 상세의 ‘정합도 판단 기준’에 서버가 반환한 원래 가중치를 표시하며 세부 배점도 펼쳐 볼 수 있습니다. 장소 카드에는 점수 기여 내역, 상세에는 ‘정합도 지표’ 막대를 표시합니다. 현재 로컬 유형 점수와 사진 기반 평가 기준을 구분하고 평가할 자료가 없는 항목은 ‘미평가’로 남깁니다.

- 로그인과 서비스 안내: `app/login.tsx`, `app/privacy.tsx`
- 기본 정보·스타일·성향 입력: `app/onboarding/`
- 자가진단과 포토 타입: `app/diagnosis/`, `app/result.tsx`
- 지역·날짜·반경·시간대 추천: `app/home.tsx`
- 장소 사진·출처·촬영 팁·지도·저장: `app/place/[id].tsx`
- 방문 후기·사진 업로드: `app/feedback/[recId].tsx`
- 저장한 장소와 계정 관리: `app/saved.tsx`, `app/settings.tsx`

프로필 필드는 모두 선택입니다. 처음에는 기본 정보 → 스타일 → MBTI → 결과 카드 → 기본 장소 추천 순서로 진행합니다. 기본 장소를 먼저 본 뒤 ‘사주·일진 추천 추가’를 선택하면 `/saju`의 별도 탭으로 이동합니다. 촬영일과 사주 정보를 확인한 다음 ‘오행·일진 장소 추천 보기’를 눌러 추가 결과를 봅니다. 기본 추천에는 사주를 적용하지 않으며 추가 탭에서 돌아와도 검색 조건은 유지합니다. 원본 생년월일시는 계산 성공/화면 닫기/로그아웃 때 입력 상태에서 지웁니다. 설정에서 입력값·오행 비율 확인, 동의 철회, 탈퇴를 할 수 있습니다.

생년월일은 `19930821`처럼 입력하면 `1993-08-21`로 표시됩니다. 실제로 존재하지 않는 날짜는 계산 시 거절합니다. 태어난 시는 풀다운 메뉴에서 12지시 또는 ‘모름’으로 선택합니다. 자시는 입력한 생일의 일주를 사용하며 모름은 시주 없이 계산합니다. 구간 선택은 정확한 분을 알 수 없어 절기 경계의 연주·월주는 근사 계산입니다.

오행 추천은 저장된 비율의 최저값을 보완 대상으로 사용합니다. 최저 비율 동률은 모두 포함하고, 해당 오행이 확인되는 장소 안에서 기본 프로필과 일진으로 순서를 정합니다. 모든 비율이 같으면 특정 오행을 부족하다고 정하지 않습니다. 비율이 없거나 올바르지 않으면 재계산을 안내합니다. 보완 대상 장소가 없으면 기본 추천으로 대체하지 않고 빈 결과를 안내합니다.

기본 카드와 상세는 ‘정합도 N점’, 추가 탭은 장소에서 확인된 보완 오행·일진 오행을 ‘목 추천’, ‘토·수 추천’처럼 표시합니다. 로컬 정합도는 기존 체형 가중치 3·MBTI T/F 가중치 2를 입력된 항목에 한해 100점으로 환산한 유형 일치도입니다. 두 항목 모두 미입력이면 점수는 null이고 ‘정합도 산정 전’을 표시합니다. 사진 분석 점수나 검증된 성격 진단 점수는 아닙니다.

## 검증

```sh
npm --prefix client test
npm --prefix app run typecheck
npm --prefix app run export -- --max-workers 2
pip install -r requirements-e2e.txt
python -m playwright install chromium
python app/e2e/release_smoke.py
```

마지막 명령은 별도 터미널에 데모 서버가 실행 중이어야 합니다. 설치된 Chrome을 이용하려면 `--channel chrome`을 추가합니다. 화면 캡처는 루트 `artifacts/screenshots/`에 저장됩니다.

## 네이티브 출시

Google/Naver/Kakao SDK는 Expo Go에서 검증할 수 없습니다. `app.config.js`는 환경 변수에 설정된 제공자의 플러그인만 추가합니다. Apple 로그인은 iOS에 제공됩니다. 실제 계정과 서명 설정 후 내부 빌드로 검증하세요.

```sh
cd app
npm run check:release
npx eas-cli build --profile preview --platform all
npx eas-cli build --profile production --platform all
```

형제 `client/`가 EAS 업로드에 포함되도록 저장소 루트를 준비해야 합니다. 운영 키·정책 URL·기기 검증·스토어 제출의 자세한 조건은 [출시 안내](../deploy/RELEASE.md), 실제 검사 결과는 [검증 상태](../RELEASE_STATUS.md)를 확인하세요.
