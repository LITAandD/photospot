# 관광공사 대표사진 연동 표본 검증

2026-11-16, 저장소 main `375b460`의 카탈로그 사본을 검사했다. 활성 장소 10,022곳, 공개 가능한 대표사진 보유 198곳, 없음 9,824곳이다. 사진이 연결된 테이블 행 수가 아니라 실제 공개 필터를 통과하는 고유 장소 수다. 운영 DB의 실시간 수치는 별도로 조회하지 않았다. [기준 카탈로그](../catalog/places.manifest.json)

## 같은 표본의 결과

11월 13일의 200곳(공공 장소 100, 카페 100) 안에서 서울·부산·강릉·제주 각 6곳을 골랐다. 공원·문화시설·관광지 각 8곳이다. 기존에 지점 대조를 마친 공공 장소 7곳을 양성 대조군으로 포함하고, 나머지는 도시별 기존 표본 순서에서 문화·관광·공원을 순환해 채웠다. 이름만 같은 지점과 대조할 수 있지만 전체 9,824곳의 확보율을 추정하는 표본은 아니다. 개별 장소의 ID·좌표·후보 수·판정은 표본 파일에 있다. [24곳 기록](data/tourism_photo_sample_24.json)

국문 API 48회(검색 30, 공통정보 9, 이미지정보 9) 중 6회는 별도 카페 대조였다. 검색 결과 없음 13곳, 동명이거나 인접·위치를 확인하지 못한 곳 4곳이었다. ‘아라’는 60건 중 첫 50건까지 조사해 전체 부재로 단정할 수 없다. 경포대오션호텔은 경포대와 다른 시설이며, 아라마루 전망대와 올리브영 검단아라점도 ‘아라’에 연결하지 않았다. 7곳의 지점 판정에는 지난 검수의 공식 출처와 이번 공통정보를 함께 사용했다. 모래시계공원은 지점이 일치해도 조감·조형물 중심 사진 때문에 통과하지 않았다.

관광사진은 별도 서비스다. 같은 키의 첫 `gallerySearchList1` 요청이 HTTP 403이었다. 포털에서 활용 중인 서비스는 1개였다. 사용자 선택에 따라 별도 신청을 진행하지 않았다. 갤러리의 추가 검수 통과 사진 수와 장소 수, 출처 간 중복 수는 **미측정**이다. 향후 이 서비스의 키워드 검색과 제목별 상세 조회 승인을 받은 뒤 같은 표본을 그대로 사용할 수 있다. 갤러리의 장소 텍스트·제목 그룹과 사진 ID는 국문 API의 장소 ID와 별개다. [관광사진 정보 API](https://www.data.go.kr/data/15101914/openapi.do)

## 새 검색 코드와 권리 필드

- 공식 분류표에서 카페는 `FD / FD05 / FD050100`, 찻집은 `FD050200`, 제과는 `FD030100`이다. 강릉 346커피스토리(법정동 51/150)와 제주 에오마르(50)는 각각 지역만 지정할 때 1건, 카페 코드를 추가하면 동일 지점 1건, 한식 중분류 FD01에서는 0건이었다. 두 카페의 대표사진 코드는 모두 Type3였다. 검색에 성공했어도 대표사진 승격이나 픽셀 분석 대상이 되지 않는다. [국문 API 및 첨부 분류표](https://www.data.go.kr/data/15101578/openapi.do)
- 장소 검색은 사진 없는 곳을 포함하는 제목순 A를 쓴다. 공식 문서의 O/Q/R은 이미지 보유 자료의 제목/수정/생성 순 정렬이다. 조회 순서는 사진 적합성이나 권리를 증명하지 않는다. 검색 권역 이름만으로 행정구역을 지정하지 않는다. 구형 CLI의 지역 번호는 호출 직전에 법정동 코드로 변환한다.
- 공통정보에는 `firstimage`, `firstimage2`, `cpyrhtDivCd`가 함께 왔다. 일치 7곳의 대표 7장은 각각 Type1이었다. 추가사진 49장은 자기 행의 `contentid`, `serialnum`, `originimgurl`, `smallimageurl`, `cpyrhtDivCd`를 확인했다. 일치 지점의 대표·추가 URL 56개 중 HTTPS 정규화 후 중복은 0건이다. 원본 내용의 모든 시각적 중복을 검사했다는 뜻은 아니다. 메뉴 전용 조회 N은 사용하지 않으며, 일반 콘텐츠 조회 Y에도 음식만 찍힌 사진이 있어 공간 시각 검수가 필요하다.
- 추가 이미지 응답에는 촬영일과 개별 촬영자 필드가 없었다. 이번 3장은 원본에 한국관광공사 기관 식별표시가 있고, 해당 파일에 Type1이 붙고, 지상에서 본 장소·공간이 확인됐다. 기관·작품명·개별 촬영자 미표기·라이선스와 원본 링크를 표시하고 정사각 프레임에서도 워터마크를 포함한 전체 구도를 유지한다. 촬영일은 미상으로 둔다. 앱의 색상·형태 분석과 AI 모델 학습은 별개이며 후자는 승인 범위에 넣지 않았다. [공공누리 제1유형](https://www.kogl.or.kr/info/licenseType1.do)
- 이촌한강공원·자갈치시장·시간박물관의 우선 후보는 이번 최종 명단에 넣지 않았다. 추가사진의 기존 시각 검수 통과 20장 중 3장만 파일별 표기와 실제 앱 사용 경로까지 확인했다. 대표 7장은 유형만 확인했으며 시각 검수 통과로 합산하지 않았다.

세 원본과 앱 표시 URL의 HTTP 200·이미지 디코딩·SHA-256 일치를 확인했다. 두 사진은 공급자 썸네일도 동일 URL이었다. 제주성지의 별도 공급자 썸네일도 200(300 × 200)이었고 앱은 검수한 HTTPS 원본을 쓴다. 최종 3장의 확인 대상에서 썸네일 오류는 0건이다. 파일별 출처·대조 근거·허용 작업·확인일과 해시는 검수 명단에 있다. [검수 명단](data/reviewed_tourism_photos.json)

[PR #24](https://github.com/LITAandD/photospot/pull/24)의 두 Commons 사진과 적용기는 그대로 재사용했다. 빈 사본이 아닌 main 스냅샷 사본에 두 번 적용한 결과 각각 2/0건, 이번 검수 명단은 3/0건이다. 기존 198곳의 대표 URL은 모두 그대로였다. 공개용 사본의 사진 보유 장소는 203곳(기존 198 + PR #24의 2 + 이번 3)이다. 저장소의 원본 SHA-256은 `2f730d5789af769bb8a519e63293cb330e3332f5f6e351c26acdd0d81e58a866`으로 유지됐다.

새 수집기는 기존 SQLite ID를 대상으로 메타데이터만 수집한다. PostGIS 장소 생성·정기 작업·운영 점수 변경은 실행하지 않았다. 승인되지 않은 후보와 내려받은 파일은 Git 또는 공개 내보내기에 포함하지 않는다. 동일 ID의 사진이 달라졌거나 지점 식별 정보가 바뀌면 중단하며, 이미 사진이 있는 지점은 새 대표사진으로 덮어쓰지 않는다.

## 테스트 범위

- 로컬 FastAPI 공개 상세와 운영용 웹 빌드를 DB 사본에 연결했다. Chrome 너비 390px와 1365px에서 세 장소를 각각 열어 원본의 실제 디코딩(폭 940px), 전체 프레임, 기관 표기, 출처·이용 조건·원본 링크 표시를 확인했다. 운영 서버·통계에는 접속하지 않았다. Android·iOS 실기기는 미검증이다.
- Python 회귀 테스트 736건 통과, 로컬 DB 등 조건부 테스트 57건 건너뜀. 저장된 Type3·권리 미확인·ND 사진의 분석·재분석·과거 근거, 위조된 후보의 공개 내보내기 제외를 검사했다. PostgreSQL 대기열 조건은 동일 행을 대상으로 한 SQL 회귀 검사에 포함했다. 로컬에서 실제 PostGIS 서비스를 실행한 결과와 구분한다.
- 클라이언트 테스트 24건, 앱 테스트 스크립트, 앱 TypeScript, Ruff, 웹 빌드를 통과했다. 갤러리 그룹 검색과 상세 처리는 응답 대역으로 검사했다. 인증된 갤러리 사진의 픽셀·장소·권리 검수는 미실행이다.

## 재현과 다음 단계

1. `catalog/places.sqlite3`를 작업용 디렉터리로 복사한다. 비공개 수집 시 서버 프로세스에만 `TOURAPI_KEY`를 연결한다. `python -m scripts.probe_tourism_photos --source kor --output artifacts/kor.json`은 24곳과 카페 대조군을 수집한다. 갤러리 승인 후에는 `--source gallery`를 사용한다. 200곳 자료를 사용하려면 기존 표본을 `--sample`로 전달하고 잔여 한도를 확인해 `--budget`을 지정한다.
2. 검수자는 장소 이름·주소·좌표·공급자 ID를 대조하고 추가사진의 개별 라이선스, 원본 픽셀·저작자 표기·권리·공간 피사체를 확인한다. 최초 사진과 각 추가사진의 권리를 서로 전파하지 않는다. 두 출처의 실제 픽셀 해시와 지점을 대조한 후에만 갤러리 순증을 센다.
3. 사본에 `python -m scripts.apply_reviewed_photos_20261113 --database <사본>`과 `python -m pipeline.tourism_photos --database <사본>`을 적용한다. `PLACE_CATALOG_DB`를 그 사본에 지정하고 `python -m scripts.export_catalog artifacts/preview.sqlite3`으로 별도 파일에 내보낸다. 공개 API에서 승인된 명단, 현재 지점, 출처·사진값을 다시 검사한다.
4. Type3·권리 미확인·CC BY-ND는 색상/형태 분석, 재분석, 기존 근거 재사용에서 제외한다. Type3은 확인된 원본의 표시·보관과 파생 처리를 구분하며 이번 승인 명단에는 없다. 좋아요로 대표사진이 바뀌면 기존 사진 식별 검증을 그대로 사용한다. [공공누리 제3유형](https://www.kogl.or.kr/info/licenseType3.do)
5. 검토자가 두 PR의 코드·사진별 표기를 확인한 뒤 별도 승인 시 운영용 스냅샷 생성과 배포를 진행한다. 이 PR에는 운영 스냅샷 변경이 없다.
