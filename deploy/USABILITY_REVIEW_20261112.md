1. 휴무 배지는 오늘·미래 날짜 모두 `선택일 휴무`로 통일했다. 서버의 선택 촬영일 판정은 그대로 사용한다.
2. 아래 운영시간 9개 레코드를 갱신했다. 미확인 3개는 확인일을 올리지 않아 `확인 필요` 상태를 유지한다.
3. 웹 의견 입력 전, 저장 버튼, 저장 후 결과와 내역을 `브라우저 메모`로 명시했다. 운영자·AI에게 보내지 않는 웹에서는 AI 동의 체크를 숨겼다. 회원 API의 실제 접수 기능은 유지했다.
4. 프로필 최종 저장 버튼 옆과 장소 저장 버튼 옆·성공 알림에 브라우저 보관, 기기 간 자동 동기화 불가, 브라우저 데이터 삭제 시 소실을 안내한다.
5. `/browse`를 별도 공개 웹 경로로 추가했다. 도시와 촬영일만 고르고 12개 장소와 대표사진·시간·지도를 볼 수 있다. 공개 API는 지정된 도시 중심 5km·12개 결과로 제한하며 프로필·현위치·사주·좋아요 식별자를 받지 않는다. 브라우저 요청은 credentials=omit이다. 개인 정합도는 산정 전으로 표시하고 거리는 도시 기준 지점의 거리임을 설명한다. 맞춤 추천은 기존 동의/연령 확인 화면으로 연결한다.
6. 카드에는 실제 평가된 양수 항목 중 기여가 큰 항목으로 한 줄 이유를 만든다. 근거가 없거나 모두 0/감점이면 잘 맞는다고 주장하지 않는다. 평가 완료 항목 수와 사진 분석 상태를 구분한다. 상세 설명은 유지한다.
7. Plus 안내/필터를 기본 추천 3개 뒤로 이동했다. 무료 이용자의 결과가3개 미만이면 홍보 안내를 숨긴다. Plus 이용자의 필터는 빈 결과에서도 다시 조건을 바꿀 수 있게 유지한다. 후원 광고는 기존의 광고 구분을 유지한다.

## 통계 정의 및 운영

- **v1 session_id**는 사실상 지속되는 브라우저 식별자였다. v2에서는 재사용·연결하지 않는다. 새 선택 저장 시 예전 키를 제거한다. 과거 데이터를 신규 방문 세션 수와 합산하면 안 된다.
- **v2 session_id**는 웹 탭의 sessionStorage, 네이티브 메모리에 보관하는 방문 ID다.30분 비활동 후 갱신한다. 새 브라우저/탭을 하나의 사람으로 묶지 않는다. 지속 브라우저 ID를 새로 수집하지 않으므로 재방문 사용자 수·고유 인원은 산출하지 않는다.
- 기존 약관/개인정보 동의를 통계 동의로 간주하지 않는다. 기존 이용자도 기본 미수집이며 `/privacy` 또는 설정의 별도 선택을 허용한 이후에만 보낸다. 거부·철회·빌드 스위치 `EXPO_PUBLIC_ANALYTICS=0`을 존중한다. 선택 표본이라는 한계가 있어 전체 방문자의 행동으로 일반화하지 않는다.
- `recommendation_request` → `recommendation_result` 또는 `empty_result`/`recommendation_error`는 request_id로 연결한다. 프로필·좌표는 props에 넣지 않는다.
- `card_impression`: 웹에서 카드50% 이상이1초 이상 노출되고 탭이 전경인 경우에만 요청/장소당1회. 마운트 또는 데이터 수신을 노출로 세지 않는다. **네이티브 앱에는 아직 viewability 어댑터가 없어 이 이벤트를 보내지 않는다.** 모바일 웹은 동일한 노출 측정이 적용된다.
- `place_view`, `map_open`, `save`(saved true/false), `client_error`를 구분한다. 상세의 데이터 재조회만으로 상세 조회를 반복 전송하지 않는다. 오류는 종류만 보내며 원문·스택은 보내지 않는다.
- `result_view`는 **포토 타입 결과 카드**, 기존 `home_first_card`는 **데이터 변경 시 반복 가능**한 구 이벤트다. 신규 home_first_card 발행을 중단했다. 두 이벤트를 순차 전환율로 나누면 안 된다.
- Wix 링크에는 `?utm_source=wix&utm_medium=website&utm_campaign=photospot` 사용 권장. UTM이 없고 Referrer 호스트가 litaandd.com/www.litaandd.com이면 wix/referral로 분류한다. Referrer 전체 주소는 수집하지 않는다. 헤더가 없으면 유입원 미상으로 남는다.
- localhost/127.0.0.1/Vercel 미리보기 호스트/`?traffic=test`/`EXPO_PUBLIC_ANALYTICS_TEST=1`은 test로 표시한다. props.schema_version=2, props.traffic=production인 이벤트만 운영 집계 대상으로 삼는다. 구 데이터는 테스트/실사용 분리가 불가능하다.
- 저장 성공204, 실패503 + Retry-After60. `analytics_event_not_stored` 및 `analytics_store_failed` 구조화 로그를 남기고, DB 예외문·세션 ID·payload는 기록하지 않는다. 클라이언트는 HTTP 실패를 성공으로 세지 않으며 화면 기능을 막지 않는다. 자동 재시도/중복 저장은 도입하지 않았다.
- 운영자가 Vercel 로그에서 위 메시지 또는 `/preview/events`503 빈도를 확인할 수 있다. **추가 제안**:5분 동안 저장 실패가 지속되면 경보를 보내는 로그 알림 설정, 일별 수집 성공 건수와 보관90일 파기 작업 점검. 외부 알림 수신처 연결은 아직 하지 않았다. 네트워크 차단으로 서버에 도달하지 않은 이벤트는 운영 로그만으로 식별할 수 없다.

## 운영자에게 실제 의견 보내기 — 제안만, 이번 배포에서 활성화하지 않음

웹의 브라우저 메모를 운영자 전송으로 전환하려면 다음을 먼저 결정해야 한다.

- 운영자 실명/상호·문의처와 개인정보 처리방침의 남은 TODO를 확정한다.
- 목적, 최소 수집 항목(분류·본문·접수 시각), 보관 기간, 삭제 방법을 정한다. 답변이 꼭 필요할 때만 별도 선택으로 연락처를 받는다. 기존 메모를 소급 전송하지 않는다.
- 기존 회원 서버의 인증된 의견 API/관리자 권한을 재사용할지, 익명 접수와 삭제용 임의 토큰을 지원할지 결정한다. 익명 접수에는 남용 제한, 입력 크기 제한, 개인정보 입력 경고, 접근 권한·열람 감사가 필요하다.
- 서버 저장 커밋 성공 뒤 접수 번호를 반환하고, 실패 시 접수로 표시하지 않는다. 운영자 이메일/Slack 알림은 수신처와 처리 권한을 정한 뒤 붙인다.
- AI 요약은 접수와 분리된 선택이다. 외부 처리/이전 및 보관 안내를 검토하고, 별도 선택 없이 전송하지 않는다. 이번 웹 메모의 AI 체크는 실제 처리와 맞지 않아 제거했다.
