# 공공데이터 혼잡도 시범 검증 · 2026-11-16

기준 커밋 `375b460`과 번들 SQLite 카탈로그를 사용했다. 주변 혼잡도와 방문일별 붐빔 전망은 공개 상세와 맞춤 상세에서 각각 독립적으로 읽는다. 추천 피드 요청, 점수 계산, 정렬에는 두 API의 데이터가 들어가지 않는다.

| 자료 | 검토 후보 | 공식 매칭 | 유효한 실데이터 확인 | 로컬 상세 표시 가능 |
|---|---:|---:|---:|---:|
| 서울시 주변 혼잡도 | 서울 명소 17곳 | 12곳 / 9개 구역 | 2곳 / 1개 구역 | 2곳 |
| 한국관광공사 방문일별 전망 | 같은 서울 후보군 17곳 | 인증 응답으로 확정한 곳 0 | 0곳, 지원 목록·날짜 범위 미측정 | 0곳 |

서울의 두 장소는 같은 공식 구역 관측을 공유한다. 관광공사 인증 오류는 장소 미지원 건수에 포함하지 않았다.

## 서울 구역 매칭

시내 궁궐·광장·공원·공연장·박물관 등 이름과 카탈로그 좌표를 확인할 수 있는 후보를 골랐다. 같은 이름의 덕수궁 node와 way 중 장소 경계를 나타내는 way의 기존 ID를 선택했다. 서울시가 2026-04-14 게시한 WGS84 경계 121개의 모든 폴리곤을 사용했다. 정확히 한 폴리곤 **내부**에 있는 좌표만 채택했다. 겹침·경계선·구역 밖 좌표는 건너뛴다. 장소가 이전하거나 이름이 바뀌면 기존 연결을 표시하지 않는다. 재검증은 별도 검토 환경에서 `pyshp`, `shapely`를 설치한 뒤 `python -m scripts.verify_crowd_areas <서울시 ZIP 경로>`로 실행한다. ZIP 해시, 좌표계, 장소 이름·좌표, 17건의 경계 판정이 모두 일치했다. 앱·서버 실행에 GIS 패키지를 설치할 필요는 없다.

## 실제 관측과 배지 만료

공개 `citydata_ppltn` 샘플의 `SeoulRtd.citydata_ppltn[0]`에서 `AREA_CD=POI009`, `AREA_NM=광화문·덕수궁`, `AREA_CONGEST_LVL=약간 붐빔`, `REPLACE_YN=N`을 확인했다. 공식 네 단계(여유, 보통, 약간 붐빔, 붐빔)를 그대로 쓴다. 아래 시각은 2026-11-16 한국시간이다. [서울시 실시간 인구 API](https://www.data.go.kr/data/15146353/openapi.do)

| 수신 시각 | 실제 관측 시각 PPLTN_TIME | 지연 |
|---|---|---|
| 13:46:01 | 13:15 | 31분 01초 |
| 13:48:17 | 13:20 | 28분 17초 |
| 13:50:48 | 13:20 | 30분 48초 |
| 13:53:18 | 13:25 | 28분 18초 |
| 13:55:48 | 13:25 | 30분 48초 |
| 13:58:18 | 13:30 | 28분 18초 |

관측 4회분이 5분 간격으로 갱신됐다. 시범 숨김 기준은 관찰한 최대 지연을 다음 5분 단위로 올린 35분에 갱신 한 주기를 더한 **관측 후 40분 이상**이다. 한 구역·짧은 시간대의 결과이므로 확대 전에 다른 구역과 시간대를 측정해야 한다. `REPLACE_YN=Y`(최근 4주 동요일·동시간 평균 대체), 플래그 누락, 미래 관측, 반환 구역 불일치, API 오류는 관측 배지를 만들지 않는다. 화면이 열린 상태에서도 만료 시 숨긴다.

두 장소가 같은 구역 URL에 요청한다. 서버 프로세스에서 동시 조회를 합치고 원응답을 최대 5분 재사용한다. Vercel 공유 캐시에는 남은 원응답 캐시 시간과 관측 유효시간 중 더 짧은 TTL을 전달한다. 로컬에서 공급자 호출 횟수와 응답 헤더를 검증했다. CDN 실제 적중 여부는 배포 전 환경에서 별도 확인이 필요하다. [Vercel 캐시 헤더](https://vercel.com/docs/caching/cache-control-headers)

`openapi.seoul.go.kr:8088`의 실제 샘플 경로는 HTTP에서 성공했다. 같은 경로의 HTTPS 8088은 TLS 오류, HTTPS 443·8089는 연결 시간 초과였다. 서울시 개인 키를 받는 코드가 없으며, 검토 환경 서버에서 `PHOTOSPOT_SEOUL_PUBLIC_SAMPLE=1`을 설정해야 익명 샘플을 읽는다. 다른 구역을 활성화하려면 인증서를 검증한 HTTPS 경로에서 해당 구역 코드·관측 시각·지연을 다시 확인한다.

## 관광공사 전망

관광공사가 문서화한 범위는 조회일을 포함한 향후 30일이다. HTTPS 목록 API에 필수 검색 조건과 덕수궁(서울 후보), 간현관광지(공식 예시)를 넣어 확인했다. 두 요청 모두 `401 SERVICE_KEY_IS_NULL`이었다. 실제 지원 관광지, 반환 날짜와 누락 빈도는 미확인이다. 승인된 전망 서비스 키를 서버에 연결하고, 실제 반환된 행정구역 코드 2개·관광지명과 카탈로그 지점의 정체성·좌표를 대조한 후 등록한다. 키만 설정해도 화면이 켜지지 않는다. [관광지 집중률 API와 지수 정의](https://www.data.go.kr/data/15128555/openapi.do)

한국시간 오늘부터 30일 안에 해당 관광지에 실제로 반환된 날짜만 쓴다. 선택일 지수와 시간상 가장 가까운 다른 날짜의 지수를 비교한다. 선택일만 있으면 비교 문구를 생략하며, 선택일이 빠지면 전망 자체를 숨긴다. 동일 날짜에 상충하는 값, 다른 지점, 범위 밖 지수, 잘린 페이지는 사용하지 않는다. 서울시 예측 필드·월별 방문객 통계로 보충하지 않는다.

## 로컬 검증과 화면

- Python 전체 757건 통과, 환경 조건에 따른 57건 건너뜀. 서울 공식 4단계, 정상 25~30분 지연과 관측 시각, 40분 만료·미래값·대체값·API 오류, 같은 구역 공유 호출, 장소 이전, 관광지 동일성·30일 경계·날짜 누락·상충값을 검증했다.
- 웹 내보내기, 앱 TypeScript 검사·단위 테스트, 클라이언트 24건, Ruff 통과. 생성한 OpenAPI와 클라이언트 타입을 포함했다.
- 로컬 Chrome 데스크톱 1100×760과 모바일 웹 390×844에서 공개 상세·동의 후 맞춤 상세를 열었다. 실제 서울 관측, 단독 전망, 두 항목 동시 표시, 방문일 변경, 미매칭, 만료·빈 응답·HTTP 503을 확인했다. 검사 중 이용 통계 요청은 0건이었다. Android·iOS 실기기와 운영 CDN은 미검증이다.
- 재현은 로컬 웹 빌드 후 샘플 설정을 켜고 `python -m uvicorn deploy.vercel.index:app --port 8774`, 이어서 `python app/e2e/crowding_smoke.py --channel chrome`을 실행한다. 관광공사 테스트 값은 브라우저 테스트에서만 주입한다.
