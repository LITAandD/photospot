# 포토스팟 추천 근거 점검 2026년 11월 13일

현재 대표사진에 적용되는 색조 분석은 123곳에서 195곳으로 늘었다. 형태는 직접 확인한 7장 중 5장만 추가 판정했고, 공식·관광기관 설명은 5개 지점에 보강했다. 미평가를 부적합으로 바꾸거나 공개 둘러보기에 개인 점수를 표시하지 않는다. 전체 정합도 산식과 우선 정렬도 유지한다.

## 기준과 운영 접근 범위

- 기준 main은 `4d5eff5`이다. 기존 공개 둘러보기·3색 UI·선택일 휴무·브라우저 메모·동의 및 연령 확인·정합도 우선 정렬·좋아요 후 대표사진 재분석을 유지했다. 원래 작업 폴더의 미커밋 변경은 건드리지 않고 별도 worktree에서 작업했다.
- 공개 카탈로그는 전체 10,443개 레코드, 활성 10,022개다. 원본 사진 6,896건 모두가 추천 가능 사진은 아니다. 지점·인물 위주/조감뷰 등의 주제 검수·재사용 권리 필터를 거쳐 대표사진이 나오는 활성 장소는 198곳이다. 아래의 ‘사진 없음’은 **추천에 사용할 수 있는 대표사진 없음**을 뜻한다.
- Neon 운영 DB에서 좋아요 합계·공개 사진 분석·최근 30일 production/v2 `card_impression` 집계만 읽었다. 개인 프로필·세션 식별자·출생 정보는 조회하지 않았다. 당시 좋아요 행 0건, 저장된 사진 분석 1건, 해당 조건 카드 노출 0건이었다. 집계 시점은 2026-11-13 12:12 KST다.
- 실제 사용자별 프로필 미입력 비율은 브라우저 보관 구조라 알 수 없다. 빈 프로필 시나리오에서는 모든 장소의 7개 항목이 `missing_input`, 정합도는 `null`이며 **정상 동작**이다. 아래는 필요한 프로필을 갖췄다고 가정한 데이터 준비 상태다.
- 검토 우선순위는 실제 인기 순위가 아니다. 유효 카드 노출 집계가 없어 도시 4곳의 기존 기준점·5km·기본 12개 결과를 사용했다. 과거 `home_first_card`·`result_view`를 카드 노출 또는 순차 전환율로 대체하지 않았다.
- 운영 `/health`의 좋아요 저장소는 최초 조회에서 실패했으나 직접 읽기 및 이후 운영 상태 연속 2회 정상 응답을 확인했다. 일시 실패 원인은 확정하지 않았다. DB 연결 설정을 임의로 변경하지 않았다.

API는 지표별 `status`로 프로필 미입력/미평가/평가 완료를, `evidence_status`로 자료 자체의 준비 상태를 따로 제공한다. 원인 코드는 `no_photo`, `analysis_pending`, `cover_mismatch`, `review_required`, `insufficient_evidence`, `ready`다. 지표별 가점 0은 확인한 특징이 서비스 취향 규칙과 일치하지 않는 경우이고, `null`은 아직 비교하지 않은 경우다.

## 점수 산식과 설명 수정

`api/catalog_scoring.py`의 명목 가중치는 28+6+6+30+10+10+10=100이다. 실제 분모는 다음과 같다.

```text
분모 D = 80 + (방문객을 실제 평가하면 10) + (공간 설명을 실제 평가하면 10)
전체 정합도 = clamp(100 × 평가된 항목 기여점수 합 / D, 0, 100)
평가한 항목 내 취향 일치도 = clamp(100 × 같은 기여점수 합 / 평가된 가중치 합, 0, 100)
```

평가된 가중치가 0이면 두 점수 모두 `null`이다. 방문객·공간 설명은 **프로필과 근거가 모두 있는 경우**만 분모에 들어간다. 나머지는 미평가·미입력이어도 분모에 남는다. 명도·채도의 기존 규칙에는 감점이 있으며 마지막에만 전체 점수를 0~100으로 제한한다. 소수점 표시·정렬은 기존처럼 한 자리다.

예를 들어 곡선 형태 30점만 평가되어 일치하면 전체 정합도는 30/80=37.5점, 평가한 항목 내 일치도는 100%, 근거 확보는 1/7이다. 일치도 100%가 장소 전체에 대한 만점이나 통계적 확률을 뜻하지 않는다. 참고 일치도는 펼쳐 보는 설명 안에만 넣었으며 추천 정렬에 사용하지 않는다.

자료 충실도는 `evidence_ready_count`로 프로필과 독립적인 근거 확보 수를 표시하고, `evidence_weight`로 명목 100점 중 확보된 가중치를 제공한다. 기존 평가 완료 항목 수는 입력까지 갖춰 실제 비교한 수다. 지도 분류 추정도 근거 수에 포함되므로 ‘검증 완료율’이라고 부르지 않는다. 사진 명도는 현장 조도·조명 실측값이 아닌 **해당 사진 픽셀의 밝기·대비**로 안내한다.

문서의 ‘고정 100점’, ‘근거만 있으면 희소 지표 반영’, ‘평가 수 우선’, 웹에도 키가 반영되는 듯한 설명을 바로잡았다. 현재 정렬은 전체 정합도 → 평가 완료 수 → 콘텐츠·휴무·사진 등 동점 보조 조건이다. 공개 둘러보기에는 개인 정합도·참고 일치도를 노출하지 않는다.

## 대표사진 연결과 형태 검토

기존 `photo_likes.rank`와 정확한 URL·원출처 일치 검사를 재사용한다. 좋아요 순위로 사진이 바뀌면 해당 사진에 저장된 근거만 사용하며, 없으면 이전 분석을 버리고 분석 필요로 표시한다. 좋아요 변경의 기존 백그라운드 분석도 유지했다. 새 클라우드 큐를 중복 생성하지 않았다.

새 배치 도구 `scripts/refresh_photo_evidence.py`는 현재 허용된 대표사진을 감사 스냅샷의 공개 좋아요 합계로 선택하고, 사진 ID가 맞을 때만 분석한다. 갤러리에 남아 있는 옛 사진도 대표사진이 아니면 거절한다. 사진 색조 72건은 사진 ID·URL·원출처·원본 URL·이미지 SHA-256·확인 시각·라이선스와 연결했다. [분석 기록](../pipeline/data/photo_analysis_manifest.json)은 색조 값과 형태 후보를 구분한다. 후보의 직선/곡선/큰 형체 신호는 확률이 아니며 점수에 자동 반영하지 않는다.

## 경복궁 방문객 통계 시범 검증

관광지식정보시스템은 새로 도입하는 출처가 아니라 기존 연간 36곳이 이미 사용하던 출처다. [통계 개요](https://know.tour.go.kr/stat/visitStatDis/introduce.do)와 [공식 통계집 목록](https://know.tour.go.kr/stat/visitStatDis/report.do)을 확인했다. 경복궁은 서울 종로구의 유료 지점으로 일치하며 주변 상권·종로구 전체 방문객으로 확대하지 않는다.

2025년 1~12월 합계 6,886,650명은 PDF 23쪽(인쇄 15쪽)의 내국인 4,102,652명 + 외국인 2,783,998명 및 월별 합계와 일치한다. PDF 발행 표기는 2026년 6월, 웹 등록일은 2026-07-31이다. 공개 첨부파일의 multipart 양식을 이용해 원문을 내려받고 추출한 숫자를 실제 표 이미지와 대조했다. PDF 표지의 공공누리 출처표시 마크와 [제1유형 이용 조건](https://www.kogl.or.kr/info/licenseType1.do)을 확인했다. 출처표시를 포함한 재현 정보·월별 숫자·파일 해시는 [시범 검증 기록](../pipeline/data/visitor_pilot_gyeongbokgung.json)에 보관한다.

이는 발권·이용 내역 기반 지점 입장객이며 개인별 순방문자나 실시간 재실 인원이 아니다. [월별 통계 화면](https://know.tour.go.kr/stat/visitStatDis/table.do)은 확인 당시 2026년 6월까지, 2분기 잠정치 안내가 있었다. 미보고는 0과 구별해야 한다. 일반 표 다운로드나 별도 API의 이용 조건은 이 PDF의 허락과 별개로 확인해야 한다.

기존 E/I는 **동일 기간 자료가 있는 36곳**만 비교한다. 동률을 중간 순위로 처리하는 백분위 `p`에 대해 E는 `10p`, I는 `10(1-p)`다. 전체 10,022곳의 방문객 순위 또는 실시간 혼잡도라 표현하지 않는다. 누락 지점은 0명으로 채우지 않는다. 기존 연간 값·가중치는 바꾸지 않았고, 시범 월별 파일은 가져오기와 점수 반영 모두 꺼져 있다.

추가 도입 전에는 통계 단위 중복, 기간 완결성·잠정치 변경, 계수 방식·운영일수·시설 규모 차이, 동률·결측 처리와 순위 민감도를 시험해야 한다. 방문객이 많은 공간에 대한 실제 이용자의 선호와 E/I 규칙의 관계도 검증해야 한다. 리뷰 수·검색량은 입장객 대체값으로 사용하지 않는다.

## 키와 J/P 및 사주

- 키·성별·출생연도: 브라우저 입력/표시에 남지만 현재 catalog의 7항목 점수에 사용하지 않는다. 170cm 실내·실외 규칙을 복원하지 않았다. 별도 PostGIS scenes 코드의 이전 규칙은 운영 웹과 구분해 문서화했다.
- J/P: `dimensions()`가 MBTI 앞 세 글자만 사용하므로 점수 0이 아니라 **점수 대상 아님**이다. 신규 가중치를 활성화하지 않았다.
- 사주·일진: 별도 요청 `use_saju`와 저장된 오행 비율이 있을 때 `personal70_daily30_v1`로 대상 오행을 고른다. 20% 미만의 보완 정도(최대 70)와 선택일 오행의 상생·동일·상극 관계(0~30)를 합산한다. 장소에 근거 있는 후보 오행의 최댓값을 사용하고 여러 태그를 중복 합산하지 않는다. 기본 7항목 정합도에는 더하지 않으며, 오행 추천에서 필터와 동점 보조로 사용한다.
- 체형·MBTI 연결은 서비스가 정한 취향 탐색 규칙이다. 과학적 체형 적합성·성격 판정이나 사진 결과를 보장하는 것으로 표현하지 않는다.

J/P의 별도 제안은 ‘계획 방문/즉흥 방문 선호’다. 지점별 공식 예약 필수 여부·입장 시간대 고정·당일 방문 가능·취소 기한·확인일·유효 기간을 먼저 확보한다. 미확인은 불리한 점수로 바꾸지 않는다. 우선 MBTI와 분리된 선택 필터로 제안하고, 이용자에게 직접 선호를 묻는 방식과 J/P 대리 규칙을 비교한다. 예약/휴일/만료 경계 테스트, 검토자 간 일치도, 동의한 이용자의 실제 선호 검증, 기존 순위와 결측 편향 비교를 통과하기 전에는 신규 점수를 넣지 않는다.

- Android·iOS 실기기 및 실제 사용자 취향 검증은 실행하지 않았다. 새 자료가 방문 만족도·전환율을 높인다는 주장은 하지 않는다.

재현은 카탈로그 복사본을 `PLACE_CATALOG_DB`로 지정한 후 `python -m scripts.audit_recommendation_evidence --output <JSON 경로>`로 수행한다. 전체 장소별 원인 JSON은 이 도구가 생성하며 실제 브라우저 프로필은 필요하지 않다. 사진 분석은 별도의 `scripts.refresh_photo_evidence` 명령으로 실행한다. 로컬 분석 도구에 Pillow·NumPy·OpenCV가 필요하며 OpenCV를 운영 서버의 요청 경로에 추가하지 않았다.

남은 우선순위는 검토 대기 87장의 형태 확인, 재사용할 대표사진이 없는 장소의 권리·지점 확보, 정확한 공간 설명 원문 추가, 방문객 통계 확대의 비교 가능성 검증이다. 지표를 채우기 위해 판정 문구·형태·방문객을 만들어 넣지 않는다.
