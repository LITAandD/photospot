사용자가 정책과 운영 배포를 승인했다. #35 병합 커밋 `e1a3eb4`를 기반으로 검증하며 #41/#42, 사진 데이터·SQLite, 운영시간·추천 점수·좋아요 대표사진 선택을 변경하지 않는다. 기존 회원 서버의 비공개 분석 업로드를 공개 사진으로 전환하지 않는다.

## 이용 흐름

공개/맞춤 장소 상세 → **내 사진을 예시로 제안하기** → 정확한 장소 ID 자동 연결 → 파일·표시 이름·선택 설명 → 인물 유형 선택 → 본인 얼굴/반사된 얼굴 영역 지정 → 동의 → 비공개 검수 요청 → 서버 처리본 확인 → 운영자 승인 후 **사용자 촬영 예시** 영역에 표시.

- 인물 사진은 본인 사진만 받는 초기 기준. 본인 여부·촬영 권한은 제출자 확인을 받고 운영자가 검토한다. 자동 신원 확인은 하지 않는다. 타인의 식별 가능한 얼굴, 아동 중심 사진, 작품·메뉴만 보이는 사진, 다른 지점, AI 이미지는 미채택한다.
- **본인 얼굴 블러 처리와 공개 동의는 별도 필수 체크**이다. 비율 슬라이더로 얼굴 전체를 지정하며 키보드로도 조정할 수 있다. 자동 얼굴 검출은 없다. 반사된 얼굴은 추가 영역으로 지정한다. 블러 처리가 완전한 익명성을 보장한다고 안내하지 않는다.
- 필수: 촬영자/권리자 허락, 정확한 장소·실제 사진, 만 14세 이상, 웹 공개, 블러·메타데이터 제거·비율 유지 리사이즈/재저장, 개인정보 처리 안내 확인.
- 선택: 추후 크롭, 사진 색상/형태 분석. 기본값은 미허용이다. 이번 코드에서는 두 작업을 실행하지 않는다. AI 모델 학습 동의는 포함하지 않는다. 앱 공개는 이번 웹 허락에 포함하지 않는다.
- 원본은 요청 처리 중 메모리에서만 해독한다. 서버는 EXIF 회전 보정 → 얼굴 영역 블러 → 최대 1600px 비율 유지 리사이즈 → 새 JPEG 생성으로 GPS·촬영일·기기정보·ICC 등을 버리고 처리본만 저장한다. 원본, 원래 파일명, 생년월일, 이메일, 프로필을 보관하지 않는다.
- 얼굴/장소/권리/촬영 예시 적합성 검수를 모두 확인해야 공개한다. 승인 시 처리본 SHA-256이 검수한 파일과 일치해야 한다.
- 대표사진과 별도 목록이므로 현재 추천 점수·정렬·분석 근거·좋아요 순위에는 영향을 주지 않는다.

## 접수 관리와 보관

로그인 없이 브라우저가 생성하는 무작위 256비트 관리 코드로 상태를 조회/철회한다. 서버에는 코드 해시만 저장한다. 코드는 URL·로그·통계·자동 localStorage에 넣지 않으며 사용자가 별도로 보관한다. 분실 시 코드만으로 자동 복구하지 않는다. 별도 문의 경로에서 권리 확인 절차를 운영해야 한다.

같은 접수번호·내용·권한으로 재전송하면 기존 접수 결과를 반환한다. 다른 내용이나 권한을 덮어쓰지 않는다. 원본 요청이 저장됐는지 불명확한 실패는 같은 바이트로 재시도한다.

운영자가 2026-11-20에 확정한 기준은 대기 30일, 승인 후 공개 365일이다. 서버 설정값과 당시 정책·동의 버전을 접수마다 저장한다. 승인에는 해당 접수의 공개기간을 사용한다. 만료 사진은 요청 시 즉시 숨기고 정리 작업이 저장 데이터를 삭제한다. 미채택은 픽셀을 즉시 지운다. 철회는 공개 중단과 픽셀·표시 이름·설명 삭제를 같은 DB 트랜잭션으로 수행하며 최소 접수 기록은 대기 기간 뒤 정리한다. 백업 삭제 시점은 저장소 사업자의 보존 설정을 확인해 정책에 명시해야 한다.

## 저장소·보안 경계

초기 소규모 시범용으로 **별도 PostgreSQL 테이블에 처리 JPEG와 검수 메타데이터를 원자적으로 저장**한다. 기존 좋아요 DB 주소를 자동 재사용하지 않는다. 별도 DSN을 명시적으로 연결해야 한다. Vercel 임시 파일시스템에 제출 사진을 보관하지 않는다. SQLite 어댑터는 APP_ENV=test이고 VERCEL이 없는 로컬 테스트 전용이다.

파일 최대 2MiB, JSON 본문 최대 3MiB, 최대 1600만 화소·정지 JPEG/PNG/WebP만 허용한다. 스트리밍 크기 제한은 Content-Length 없이도 적용한다. 전체 처리본 100MiB/일 100접수/주소별 일 5접수의 시범 상한이 있다. 주소는 일별 HMAC만 보관하며 원 IP를 쓰지 않는다. 트랜잭션 잠금으로 다중 프로세스에서도 중복/용량 한도를 확인한다. 대규모 확대 전에 별도 비공개 객체 저장소로 이관할 것. 유료 플랜/버킷은 이번에 생성하지 않았다.

동일 Origin JSON 제출만 받으며, 관리에는 Bearer 코드가 필요하다. 공개 이미지는 승인·미만료 상태와 활성 장소를 매번 검사하고 no-store로 제공한다. 중단/철회 뒤 CDN 캐시로 재공개하지 않는다. 이미 타인이 저장한 사본을 회수할 수 있다고 약속하지 않는다. 접수 저장소 장애는 사진 영역 오류로 끝나고 기존 추천은 유지한다. 기존 통계 동의를 건드리지 않고 새 접수 이벤트를 보내지 않는다.

## 운영자 절차 (공개 관리자 API 없음)

권한 있는 서버 환경에서만 아래 명령을 실행한다. 비밀 값은 서버 환경변수로 제공하고 채팅/명령행 인수/저장소에 넣지 않는다.

```sh
python -m api.visitor_photo_admin migrate

python -m api.visitor_photo_admin review RECEIPT_ID --sha256 REVIEWED_IMAGE_SHA256 --reviewer OPERATOR_ID --decision approve --place-confirmed --rights-confirmed --faces-confirmed --scene-confirmed

python -m api.visitor_photo_admin prune --apply
```

queue는 블러 처리본과 검수 정보를 담은 **비공개 로컬 HTML/사진 묶음**을 만든다. 공개 웹 경로·Git에 올리지 말고 검수 직후 폐기한다. 접수 상태가 바뀐 뒤 이전 묶음으로 승인하면 거절된다. 검수자는 실제 지점, 촬영 허락, 얼굴/거울 반사/타인, 상설 공간·구도를 직접 확인한다. 검수 결과와 체크 항목은 저장된다. 자동 검수·자동 승인은 없다.
