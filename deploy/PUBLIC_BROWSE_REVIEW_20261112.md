# 공개 탐색 운영 화면 개선 · 2026-11-12

## 기준과 유지 범위

- 기준: main `17442fd5308e9253259e21e0d2475d7bdaa16554` (PR #21), [기존 이용성 검토](USABILITY_REVIEW_20261112.md).
- 변경 전 운영 `/browse?traffic=test`에서 개인화 전 `평가 0/7항목`, `정합도 산정 전`, 반복 추천 문구를 재현했다.
- 기존 공개 탐색, 선택일 휴무, 브라우저 의견 메모와 저장 안내, 3색 테마·정사각형 사진, 개인화 정합도 우선 정렬, 필수 동의·연령 확인, 선택적 통계 v2는 유지한다.
- 원래 작업 폴더의 미커밋 변경을 건드리지 않고 최신 main의 별도 작업 브랜치에서 수정했다.

## 반영한 동작

1. 공개 카드: 개인 정합도·평가 수·공통 추천 이유를 숨긴다. 검토한 대표사진 형태 또는 출처가 있는 공간·촬영 특징만 최대 두 줄의 항목으로 표시한다. 알려진 내용이 없으면 빈 항목을 만들지 않는다.
2. 공개 목록: 전체 유효 후보에서 이용 가능한 사진 보유 여부를 먼저 정렬한 다음 12곳을 고른다. 사진 없는 장소에는 `공간 사진 수집 중`을 표시한다. 기존 사진 적합성·조감뷰·인물 제외, 재사용 권리, 좋아요에 따른 대표사진 선택은 그대로 적용한다. 개인화 목록의 정합도 우선 정렬에는 영향을 주지 않는다.
3. 공개 상세: `/browse/{place_id}?city=…&date=…`에서 사진·출처, 주소, 확인된 공간·촬영 안내·입장료·예약 조건을 볼 수 있다. 개인정보나 로그인 쿠키 없이 공개 API로 조회한다. 기존 개인화 상세는 유지한다.
4. 운영시간: 선택일 요약을 먼저 보여주고 시간표·출처·확인일·변동 주의사항은 펼쳐 본다. 만료 경고는 접힌 상태에서도 보인다.
5. 맥락 유지: 도시·날짜·장소를 URL과 최대 2시간의 탭 내 맞춤 설정 상태로 보존한다. 설정 중단 시 보던 상세/목록으로 돌아가고, 완료 시 선택한 도시 기준점·촬영일을 홈에 적용한다. 보던 장소를 다시 여는 버튼도 제공한다. 프로필이나 동의값을 URL에 넣지 않는다.
6. 거리: 서버가 실제 계산에 사용한 기준점 이름과 `직선거리`를 카드·상세에 표시한다. GPS·도보 거리로 소개하지 않는다. 도시 미선택, 조건 변경 로딩, 빈 결과, 없는 장소에 각각 안내와 다음 행동을 제공한다.
7. 용어: 웹 설정과 안내의 `회원 탈퇴`는 `이 브라우저의 데이터 삭제`, 로그아웃은 `맞춤 추천 종료`로 바꿨다. 실제 계정 API를 사용하는 설치형 앱의 계정 삭제 표현은 유지한다.

## 실제 장소 오류 제보: 비활성 구현안

확인된 홈페이지 공개 연락처는 [LIT A&D](https://www.litaandd.com/)의 `info@litaandd.com`, `+82-2-6953-1620`이다. 이것만으로 해당 연락처를 포토스팟 제보 담당 창구나 개인정보 보호책임자로 확정하지 않는다. 저장소 정책 문서의 운영자·문의 이메일·시행일도 아직 TODO다. 따라서 이번 배포에는 제보 전송 버튼·서버 저장·이메일 발송을 추가하지 않는다. 브라우저 메모는 계속 브라우저에만 남으며 과거 메모의 이관·전송도 없다.

정책 확정 후 별도 동의를 거쳐 구현할 안:

- 장소 ID, 오류 유형(시간/휴폐업/주소/사진/기타), 짧은 설명(선택·500자), 근거 URL(선택)만 받는다. 이름·전화·이메일·위치·프로필·사진 첨부는 기본 수집에서 제외한다. 본문에 개인정보를 적지 않도록 입력 전에 안내한다.
- 전송 버튼 직전에 운영자, 목적, 항목, 보관 기간, 삭제 방법과 전송 사실을 명시한다. 브라우저 메모와 별도의 빈 입력 화면으로 시작한다. 자동 AI 분석이나 외부 게시를 하지 않는다.
- 서버가 저장 완료를 확인한 뒤 접수번호와 삭제용 비밀 영수증을 한 번 제공한다. 서버에는 삭제 비밀의 해시만 둔다. 중복 클릭 방지, 속도 제한, 입력 길이·URL 검사, 관리 권한·접근 기록을 적용한다. 이용자 URL은 서버가 자동 방문하지 않도록 SSRF를 피한다.
- 운영자는 인증된 관리 화면에서 대기/확인중/반영/미확인 상태를 처리한다. 원문과 개인정보를 애플리케이션 로그·통계·오류 추적 서비스에 넣지 않는다. 접수 실패율·대기 건수·오래된 미처리 건수만 모니터링한다. 이메일 알림을 붙이는 경우 본문 없는 접수 알림과 승인된 수신자만 사용한다.
- 보관안은 처리 종료 후 30일, 미처리도 최대 90일 후 삭제로 제안한다. 실제 기간, 백업 삭제, 악성 제보 대응, 삭제 영수증을 잃은 경우의 절차는 운영자가 확정해야 한다. 기술 로그의 IP 보관 여부·기간과 호스팅 수탁/국외 이전 안내도 함께 확인한다.

**남은 결정**: 법적 운영 주체·담당자, 승인된 제보 문의처, 최종 수집·보관·삭제 방침과 시행일, 관리 화면 접근 계정, 저장소·알림 제공자, 응답 및 삭제 처리 기한. 확정 전에는 기능을 켜지 않는다.

## 검증

- 로컬 Python: 711 통과, DB 환경이 필요한 항목 등 58 건너뜀. GitHub CI의 PostgreSQL 통합 검사는 별도 확인한다.
- 앱 전체 단위/컴포넌트 검사, TypeScript 검사, 클라이언트 생성·빌드, Python ruff/mypy, 운영 형태 웹 번들 빌드 통과.
- 새 공개 탐색 E2E: Chromium 390×844 터치 설정과 1280×900에서 도시 미선택, 도시·달력 날짜 변경, 카드 정보, 상세 열기·목록 복귀·새로고침, 맞춤 설정 중단/완료 후 맥락 유지, 없는 장소, 기본 통계 미전송 통과. CI에도 추가했다.
- 오늘 및 미래 선택일의 휴무 판정 회귀 검사와 사진 우선 정렬(결과 제한 적용 전), 공개 상세 범위/404, 방문 정보 출처·만료·현재 대표사진 일치 검사를 통과했다.
- 테스트는 로컬 새 브라우저 프로필을 사용하고 통계 동의는 기본 끔을 유지했다. 운영 읽기 점검은 `traffic=test`로 시작한다. 운영자의 기존 동의·브라우저 메모를 전송하거나 선택을 변경하지 않는다.
- Android·iOS 실기기는 연결된 장치를 확인할 수 없어 미검증이다. 위 모바일 검사는 모바일 화면 크기·터치 설정의 Chromium이며 Android Chrome/Safari 실기기 검증을 대체하지 않는다.

배포 후 실제 모바일 기기에서는 뒤로가기 제스처, 새로고침, 작은 화면의 카드·달력·출처 펼침, 통계 선택 유지까지 추가 확인할 것을 권장한다.
