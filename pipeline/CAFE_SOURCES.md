# 카페 DB 채우기: 네이버 + 인스타그램

카페는 TourAPI에 거의 없다. **네이버로 목록을 만들고, 인스타그램으로 사진·인기를 채우고, 사장님 등록으로 확정**하는 3단계다.

## 1단계 · 네이버 지역 검색으로 목록 만들기
```bash
export NAVER_CLIENT_ID=... NAVER_CLIENT_SECRET=...      # 네이버 개발자 센터 > 애플리케이션 > 검색 API
python -m pipeline.run harvest-naver-cafes --areas 성수동,연남동,을지로,한남동,익선동,해운대,전포동,애월,함덕 --target 500
```
- 검색어 하나에 5곳만 나오므로 **동네 × 테마**(한옥·플라워·화이트·미니멀·빈티지·루프탑·오션뷰·정원·베이커리·감성·뷰·일반) 검색어를 돌려 모은다. 동네 9개 × 테마 12개 = 108회 → 최대 540곳. 하루 25,000회라 여유가 크다.
- 리뷰 많은 순(`sort=comment`)으로 받아 인기 카페가 먼저 들어온다.
- 네이버 항목엔 장소 ID가 없어 **이름+도로명주소**로 중복을 판단하고, **지점을 포함한 장소명만 사용하는** 네이버 지도 검색 딥링크를 저장한다.
- **검색에 쓴 테마가 초기 태그**가 된다 (신뢰도 0.25, 검수 대기열). 사진이 없으므로 아직 `photos` 행은 없다.
- 네이버 검색 API가 NAVER API HUB로 이전 중이라 엔드포인트·헤더가 바뀌면 `naver_local.py`의 `SEARCH_URL`·헤더만 고치면 된다.

## 2단계 · 인스타그램으로 사진 분석·인기 신호
```bash
export INSTAGRAM_ACCESS_TOKEN=... INSTAGRAM_USER_ID=...  # 우리 비즈니스 계정 (Meta for Developers 앱, instagram_basic + pages 권한)
python -m pipeline.run enrich-instagram --limit 30      # 매주 1회 정도
```
- 사진 없는 카페부터 처리한다. **공식 계정(`places.instagram_handle`)이 있으면** 비즈니스 디스커버리로 그 계정 게시물을 쓰고(시간당 200회), 없으면 카페 이름 해시태그의 인기·최근 게시물을 쓴다(**7일에 해시태그 30개**).
- 이미지는 **저장하지 않는다.** 메모리에서 색 통계와 AI 판정만 뽑아 `external_media`에 결과(숫자·라벨·permalink)만 남긴다. 그 결과가 우리 사진과 함께 집계돼 초기 태그를 덮어쓴다.
- 최근 30일 게시물 수를 `trend_signals`에 기록한다 → 뜨는 카페 감지, 태깅 우선순위.
- 앱에서 게시물을 보여줄 땐 permalink로 공식 임베드(oEmbed)만 쓴다.
- **출시 전 법률 검토 필요:** 해시태그 API 미디어를 분석 목적으로 처리하는 범위, Meta 플랫폼 약관. 사용자 사진(동의)과 사장님 사진은 이 제약이 없다.

## 3단계 · 사장님 등록으로 확정
`place_owners`로 사장님이 계정을 연결하면 `instagram_handle`을 채우고 사진을 직접 올리게 한다(`owner_upload`). 이 사진이 가장 신뢰도 높은 원천이고 약관 문제가 없다.

## 현재 웹·인증 API 공통 추천

2026-10-07부터 기본 `catalog` 백엔드는 웹과 인증 API가 함께 사용합니다. 공개 SQLite 테이블을 `python -m scripts.export_catalog`으로 배포 이미지에 포함합니다. 아래 PostGIS 수집 명령은 기존 `scenes` 백엔드용입니다.

`python -m pipeline.cafe_photos`는 `data/cafe_photos.json`의 지점 확인 사진을 연결합니다. Commons에서 재사용 가능한 사진 메타데이터를 검증하고 이름·좌표 대조 기록을 남깁니다. 지점당 대표 파일과 여러 추가 파일을 지원하며 정기 Commons 갱신에도 유지합니다. 브랜드 전체 사진은 지점 사진으로 쓰지 않습니다. `catalog_visuals`로 사진의 색 통계를 계산하며 검토된 공간 특징은 해당 파일에만 적용합니다.

`python -m pipeline.official_cafe_photos`는 [스타벅스 공식 매장찾기](https://www.starbucks.co.kr/store/store_map.do)에 공개된 지점별 대표 사진과 갤러리를 연결합니다. 현재 카탈로그 지역에 해당하는 시·도 목록을 조회하고 브랜드·지점명·도로명주소·좌표를 비교합니다. 지점명이 없는 매장은 50m 이내이며 다른 지점과 충분히 떨어진 경우에만 연결합니다. 명시된 지점명이 다르거나 가까운 매장 두 곳을 구분할 수 없으면 제외합니다. 동일 공식 지점에 여러 지도 노드가 있어도 한 곳만 선택합니다.

사진은 공식 CDN의 해당 지점 번호가 포함된 경로만 사용합니다. 앱 조회 중 외부 수집은 실행하지 않으며 메타데이터는 7일 캐시, 요청은 1.2초 이상 간격으로 순차 처리합니다. 지점별 전체 응답이 성공한 경우에만 이 출처의 기존 갤러리를 갱신하고, Commons 갱신은 공식 사진을 삭제하지 않습니다. 공식 지점명과 주소는 앱 조회에만 보완하여 OSM 원본 행을 보존합니다. 명칭·좌표가 바뀐 카페는 조회 시에도 재확인하여 이전 브랜드의 사진을 숨깁니다.

공식 사진은 외부 URL을 연결하고 `© Starbucks Korea` 및 지점 출처를 표시합니다. **공식 공개 사진은 CC 라이선스가 아니며 재배포 권한을 확보했다는 뜻이 아닙니다.** 공개 연결 허용 범위와 상업 서비스 이용 권한은 운영 배포 전에 확인해야 합니다. Commons 사진에는 원래의 작가·CC 이용 조건을 별도로 표시합니다. 최신 연결 수와 실패 항목은 `artifacts/cafe-official-photo-audit.json`, 배포 범위는 `RELEASE_STATUS.md`를 참고하세요.

위 PostGIS 수집 과정과 별도로 로컬 `storage/places.sqlite3`에는 `cafe_popularity.py`가 확인된 지점별 집계 또는 네이버 리뷰순 검색 결과를 연결합니다. [실제 데이터 안내](../REAL_DATA_TEST.md#사진카페-리뷰-우선-추천)의 입력·갱신 명령과 적용 범위를 참고하세요. 실제 네이버 공개 집계는 현재 2곳이며 Instagram 실제 값은 미연결입니다. 인증 정보가 없으면 API 자동 갱신은 실행하지 않습니다. 미확인값과 만료값은 추천 가산에서 제외합니다.

## 공개 네이버 영업시간

`place_hours.py`는 공식 지점의 날짜별 시간, 공개 네이버 확인 시간, OSM 등록시간을 출처별로 읽어 목록·상세에 제공합니다. 네이버 확인 범위는 카페 5곳·여행 명소 3곳(총 9개 카탈로그 ID)입니다. 스타벅스 346개 지점은 `official_place_hours.py`로 공식 매장별 게시 날짜를 보존해 수집하며, 다른 주로 반복 적용하지 않습니다. OSM 복합 시간식은 원문 조건을 유지합니다. 전체 925곳에 시간 안내가 연결됐고 일반 방문이 가능한 사진 연결 카페 349곳은 모두 포함합니다. 서울리즘은 대관 전용 전환을 확인해 일반 방문 추천에서 제외했습니다. 세부 범위와 갱신 명령은 [실제 데이터 안내](../REAL_DATA_TEST.md#네이버지도-검색과-영업시간)를 참고하세요.

## 한계
- 네이버 지역 검색 API에는 **영업시간·리뷰 수·폐업 여부**가 없습니다. 공개 장소 페이지에서 확인한 시간과 집계는 별도로 관리합니다. 폐업 감지는 사용자 제보(후기 "문 닫았어요")와 정기 재검색으로 보완.
- 해시태그가 흔한 이름(예: "카페 온")이면 다른 가게 사진이 섞인다. 집계 신뢰도가 낮게 나오면 검수 대기열에서 걸러진다.
