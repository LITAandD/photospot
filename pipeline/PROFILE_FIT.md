# 카탈로그 정합도 v3

2026-10-08 요청 기준. 공개 웹과 인증 API의 `catalog` 추천에 함께 적용한다.
사용자가 정한 촬영 장소 취향 규칙이며, 성격에 따른 과학적 적합성 판정은 아니다.
PostGIS 장면 엔진의 SQL/샘플 규칙은 별도 버전이다.

## 점수와 정렬

| 입력 | 관찰/근거 | 배점 | 일치 기준 |
| --- | --- | ---: | --- |
| 웜/쿨 | 대표 사진 색조 | 28 | 난색→웜, 한색→쿨, 중성 0.5 |
| 세부 톤 | 사진 명도·채도 | 6 + 6 | 기존 세부 톤 규칙과 감점 유지 |
| 체형 | 검토한 대표 사진의 배경 형태 | 30 | 곡선→웨이브, 직선→내추럴, 큰 형체→스트레이트 |
| E/I | 2025년 연간 장소 입장객 수의 전역 순위 | 10 | E는 많은 곳, I는 적은 곳 |
| S/N | 네이버지도·Instagram 공간 설명/평가의 명시 문구 | 10 | 디테일 / 컨셉, 양쪽 확인 시 0.5 |
| T/F | OSM 장소 유형·건축/자연 태그 | 10 | 건축물 / 자연물, 혼합 시 0.5 |

기본 배점은 **고정 100점**이다. 획득 배점 합을 0~100 범위로 제한하고 소수점
한 자리로 표시한다. 미입력·미평가도 전체 배점에 포함하지만 점수는 더하지 않는다.
체형 하나만 일치하면 30/100점이며 100점으로 확대하지 않는다. `null`(미평가)과
실제 평가 결과 0점은 구별한다. 키는 프로필에 남지만 장소 채점·정렬에 사용하지 않는다.
J/P는 검토안으로 안내하고 배점에서 제외한다. 사주·일진은 별도로 평가한다.
상세 화면의 파이차트는 감점 반영 후 최종 점수와 100점까지의 나머지를 표시한다.
나머지에는 미획득·미평가·미입력이 포함되므로 부적합 비율로 해석하지 않는다.
지표별 점수·상태는 항상 보이며, 근거·방문객 통계·원문 출처는 각 지표의 펼침창에서 확인한다.

추천 순서는 전체 후보의 전체 정합도 내림차순 → 동점이면 평가 완료 항목 수 내림차순이다.
화면에 표시하는 소수점 한 자리 점수를 기준으로 정렬하며, 산정 전 장소는 0점 장소보다 뒤에 둔다.
0점·감점도 평가 완료로 세며, 미평가/미입력은 세지 않는다. 최대 7항목이다.
동점은 오행 점수(오행 추천일 때), 사진 유무, 공개 인기 지표, 거리, ID 순으로 해소한다.
기존 MBTI 유형의 별도 2점 보너스는 제거하여 T/F를 중복 반영하지 않는다.

## E/I: 2025년 입장객

[한국문화관광연구원 관광지식정보시스템 통계집](https://know.tour.go.kr/stat/visitStatDis/report.do)의
**2025년 주요관광지점 입장객통계집**(게시 2026-07-31)의 2025년 `계` 열을 사용했다.
서울·부산·강릉·제주 표와 활성 카탈로그를 대조하여 **36개 통계 단위**를 연결했다.
`data/visitors_2025.json`에 실제 카탈로그 ID·이름·OSM 출처, 통계 단위 이름,
방문객 수, 책자 쪽수와 PDF 페이지, 공표일과 확인일을 기록한다.
예: 경복궁 6,886,650명, 국립중앙박물관 6,507,483명. 보도자료의 잠정 집계보다
확정 통계집을 우선했다. `-`는 미집계이며 실제 숫자 0과 구별한다.

- 기간은 촬영일·조회일·월 변경과 관계없이 **2025-01~2025-12**로 고정한다.
- 공식 연간 합계를 `catalog_annual_visitors`에 저장한다. 연간 수치를 월별로 나눠 만들지 않는다.
  같은 장소의 2025년 12개월 월간 수치가 전부 있으면 합산 가능하나 공식 연간 값이 우선한다.
- 도시 총방문객, 리뷰 수, 검색량, SNS 좋아요, 일부 행사/기간 수치는 대체 지표로 받지 않는다.
- 같은 통계 단위를 여러 OSM 객체에 중복 등록하지 않는다. 대표 객체 하나만 연결하며
  부분 시설·지명 유사 카페에 큰 관광지 전체 수치를 붙이지 않는다. 오죽헌·시립박물관,
  용두산공원(부산타워)처럼 원문의 집계 범위 이름도 상세에 함께 표시한다.
- 순위는 반경·도시·유형 필터 전의 전체 활성 카탈로그 중 동일 기간 집계가 있는 장소로 계산한다.
  결측은 순위 밖이며 0명으로 간주하지 않는다. 전체 DB 수와 실제 비교 대상 수를 함께 표시한다.
- 동점은 공동 순위와 평균 백분위를 부여한다.
  `p = (더 적은 장소 수 + (동점 수-1)/2) / (집계 장소 수-1)`.
  E는 `10p`, I는 `10(1-p)`. 비교 대상이 2곳 미만이면 채점하지 않는다.
- 이는 연간 입장량의 상대적 지표다. **촬영 시각의 혼잡도는 아니며** 장소 면적과 운영일수에
  영향을 받는다. 방문객 자료가 없는 카페를 한적한 장소라고 단정하지 않는다.

## S/N: 공간 설명의 명시 문구

`data/place_descriptions.json` / `catalog_descriptions`에 짧은 공간 발췌문·출처·확인일을 저장한다.
2026-10-08 검토한 카탈로그 **9곳** 중 판정 가능한 곳은 **2곳**(런던베이글 안국,
커피한약방 을지로)이며 모두 네이버의 공간 평가 `컨셉이 독특해요`가 확인됐다.
Instagram 등 나머지 7곳의 공간 설명에는 지정 문구가 없어 미평가로 남겼다.
전체 10,022개 장소의 설명을 모두 검토했다는 뜻이 아니다.

- S: `디테일`, `섬세`, `정교`, `세밀`, `detail(s)`.
- N: `컨셉`, `컨셉트`, `콘셉트`, `테마`, `세계관`, `concept(s)`, `theme(s)`.
- 한쪽 문구만 확인되면 해당 선호 10점/반대 선호 0점, 둘 다 확인되면 양쪽 5점,
  어느 쪽도 확인되지 않으면 미평가다. 문구 반복이나 게시물 양으로 점수를 증폭하지 않는다.
- 음식·서비스·다른 지점 평가, 해시태그·닉네임, 네이버 AI 요약, 브랜드 전체 소개는 제외한다.
  예를 들어 커피한약방 리뷰의 ‘살얼음 디테일’은 음료이면서 경동시장점 후기로,
  을지로 공간 S 판정에 사용하지 않았다. 검토자는 공간에 관한 짧은 문장만 채택해야 한다.
- 부정 표현(없다·아니다·않다·부족·별로 등)이 있는 문장은 보수적으로 제외한다.
- 수집기는 지점 ID·OSM 출처·이름·좌표, 허용된 네이버 장소/Instagram 게시물 URL,
  확인일, 공간 범위 표시를 검증한다. 동명이점의 글을 자동 연결하지 않는다.
- 상세에 발췌문·실제 매칭 단어·원문 링크·확인일을 표시한다. 기존 사진 분석의
  `place_character`/`photo_mood`를 이 출처 검토 대신 사용하지 않는다.

## T/F: 건축물과 자연물

`catalog_mbti.space_nature`는 OSM의 유형과 태그를 근거로 분류하며 상세에 실제 근거 링크를 표시한다.
카페·베이커리·식당·박물관·갤러리·문화시설, 건물/궁궐/성문 등의 태그는 건축물 중심이다.
공원·수변·자연 명소, 숲/해변/산/물/절벽/정원 등의 태그는 자연물 중심이다.
둘 다 해당하면 혼합(양쪽 5점), 불명확한 일반 명소·전망대·유적은 미평가다.
유형 추정이라는 표시를 유지하며 사진 전체의 건축/자연 면적을 실측했다고 표현하지 않는다.

## J/P 검토안: 일정 확정 가능성 / 방문 자유도

| 축 | 제안 근거 | 주의점 |
| --- | --- | --- |
| J 일정 확정 가능성 | 확인된 운영/휴관일, 확정 가능한 입장 시간, 명시된 관람 동선·소요 시간 | 예약 필수라는 사실 자체에 가점을 주지 않는다. 예측 가능성이 핵심이다. |
| P 방문 자유도 | 예약 없이 입장, 자유 관람·산책, 방문 시간 선택 폭, 중간 합류·이탈 가능 | 야외 여부·방문객 수로 대체하지 않는다. |

같은 장소가 두 성격을 모두 가질 수 있다. 실제 예약 조건·일정 자료와 점수 설계를
확정하기 전에는 **배점 0, 정합도 항목 수에도 미포함**으로 유지한다. 현재 화면에는 검토안만 안내한다.

## 갱신

```powershell
.venv/Scripts/python.exe -m pipeline.catalog_visitors pipeline/data/visitors_2025.json --annual
.venv/Scripts/python.exe -m pipeline.catalog_mbti pipeline/data/place_descriptions.json
.venv/Scripts/python.exe -m scripts.export_catalog
```

전체 입력을 검증한 뒤 트랜잭션으로 저장한다. 방문객은 2025년 확정 연간 수치만 받으며
같은 통계 단위의 다른 장소 중복은 거절한다. 설명은 더 오래된 검토일로 덮어쓰지 않는다.
추천 요청 중 외부 검색·스크래핑은 하지 않는다. 출처가 사라지거나 공간이 개편되면
해당 근거를 재검토하여 수정/삭제하고 공개 스냅샷을 다시 배포해야 한다.

## 사진 근거와 갱신

- `data/catalog_photo_reviews.json`: 2026-10-07 실제 대표 사진 517장 검토. 493장에 형태를 기록한다.
  직선은 기둥·창틀·난간 등 반복되는 곧은 윤곽, 곡선은 아치·원형 지붕·곡선 길 등의 우세한 윤곽,
  큰 형체는 독립된 큰 건물 덩어리·석재·바위 등 부피감 있는 형체를 기준으로 구분한다.
  작게 보이는 로고 원형/글자는 우세 형태의 근거로 사용하지 않는다.
- 검토는 정확한 장소 ID, 사진 URL, 원문 URL에 묶인다. 다른 사진으로 바뀌면 재검토가 필요하다.
  확실한 우세 형태가 없는 사진 24장은 형태를 제외하고, 그 중 공간을 판단할 수 없는
  인물·문서·물품 클로즈업 6장은 색조를 포함한 사진 정합도 근거에서 제외한다.
- 현재 추천은 대표 사진 한 장 기준이며 장소 전체·모든 시간대의 특성을 보장하지 않는다.
- `python -m pip install -r requirements-analysis.txt` 후
  `python -m pipeline.catalog_visuals --limit 10000 --workers 2`로 색 분석/형태 검토 후보를 갱신한다.
  OpenCV 윤곽 분석은 검토 후보 생성용이다. 형태 오분류를 확인했으므로 **검토되지 않은
  자동 형태는 서비스 점수에 사용하지 않는다**. 검토 결과를 데이터 파일에 추가한다.
  공개 이미지 캐시는 `storage/analysis-photos`에만 저장하며 배포하지 않는다.
- 사진이 삭제되거나 연결이 달라지면 기존 근거를 무효화한다. 요청 처리 중에는 외부 사진을 내려받지 않는다.

OpenCV 참고: [직선 검출](https://docs.opencv.org/4.x/d9/db0/tutorial_hough_lines.html),
[윤곽 특징](https://docs.opencv.org/4.x/dd/d49/tutorial_py_contour_features.html).
